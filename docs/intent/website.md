## Rendering and routing

Ordinary content and language links work without JavaScript; statistics show a localized enable-JavaScript message. English and Spanish are separate HTML documents. The statistics privacy pages are `/content-statistics/privacy/` and `/es/content-statistics/privacy/`, with their own canonical/alternate metadata and ordinary navigation back to the home-page sections.

A small viewer-request function first redirects only the exact `www.guilleojeda.com` host to `https://guilleojeda.com`, retaining the complete URI and raw query string. The apex and CloudFront hostnames continue through the normal routing: the two home and two statistics privacy routes serve their exact directory `index.html` objects. Known routes without a trailing slash redirect to it while retaining the query. Assets and other paths pass through; unknown paths return HTTP 404 with links to both home pages rather than a successful homepage response.

The apex A and AAAA records alias the existing CloudFront distribution; `www` uses the same aliases so the function can issue the canonical redirect. Registration remains at GoDaddy. ## Delivery and recovery

Pull-request builds have no AWS deployment privileges and pass the resulting artifact to the main-branch deployment job. That job uses GitHub OIDC and a resource-scoped AWS role. Repository variables contain public identifiers and the deployment URL, not long-lived AWS credentials. Change-set creation is restricted by name and template URL; inspection and execution are scoped to the existing stack. Lambda actions target only the collector; `iam:GetRole` reads are limited to the existing collector execution-role and scheduler-role ARNs and the same-stack `SiteDeploymentRole-*` prefix used to resolve `DeploymentRoleArn` without a self-reference; the `HostedZoneNameServers` output read handler uses only `route53:GetHostedZone`, `route53:ListTagsForResource`, and `route53:ListQueryLoggingConfigs` on `SiteHostedZone`; the `DistributionDomainName` read handler uses only `cloudfront:GetDistribution`, `cloudfront:GetDistributionConfig`, and `cloudfront:ListTagsForResource` on `SiteDistribution`; these are read-only handler permissions and add no DNS or distribution configuration/tag writes; role passing is limited to the collector execution role and Lambda service. The deploy script enforces the code-only template/change-set rule; IAM scopes the resources but does not encode the nested `Code.ZipFile` comparison. The script rejects a stack service role so the existing caller permissions remain the effective boundary. CI cannot invoke the collector, write the public aggregate, or read collector inputs and credentials.

Production publication is serialized. A superseded main-branch push must not replace a newer build. Hashed assets are uploaded before mutable HTML and metadata; old hashed assets are retained so previously cached pages remain usable. An age-only deletion rule could remove a current asset that has not changed, so none is used. This accepts small storage growth in exchange for simple, reliable cached-page and rollback behavior; reconsider cleanup only if measured growth warrants it.

After a one-time operator update of the CI policy, collector code-only changes deploy through the existing CloudFormation stack at the start of the serialized main-branch site job. The renderer embeds the authoritative collector source, just as it embeds the routing function. CI compares the deployed original template with the rendered template and permits only `ContentStatsCollector.Properties.Code.ZipFile` to change. Its change set must include one in-place update to that Lambda. CloudFormation may also preview `ContentStatsSchedulerRole`, `ContentStatsDailySchedule` and `SiteDeploymentRole`. The script accepts at most one `ContentStatsSchedulerRole` preview only when every detail is a dynamic `Properties.Policies` reference caused by `ContentStatsCollector.Arn`; one `ContentStatsDailySchedule` preview only when every detail is a dynamic `Properties.Target` reference caused by either `ContentStatsCollector.Arn` or `ContentStatsSchedulerRole.Arn`; and one `SiteDeploymentRole` preview only when every detail is a dynamic `Properties.Policies` reference caused by `ContentStatsSchedulerRole.Arn`. Direct, static, replacement, duplicate or unknown changes fail before execution. It preserves existing stack parameters and waits for completion. It keeps the Lambda signed code URL in memory, fetches the archive without logging the URL or source, and uses a temporary archive with the system `unzip` command to verify the deployed `index.js` bytes and hash. The scoped Lambda permissions cover the CloudFormation handler's code/configuration, tag and metadata operations. `iam:GetRole` reads are limited to the two existing role ARNs and the same-stack `SiteDeploymentRole-*` prefix needed to read the `DeploymentRoleArn` output without a self-reference; the full Route53 read handler (`GetHostedZone`, `ListTagsForResource`, `ListQueryLoggingConfigs`) reads only `SiteHostedZone` for `HostedZoneNameServers`, and the full CloudFront read handler (`GetDistribution`, `GetDistributionConfig`, `ListTagsForResource`) reads only `SiteDistribution` for `DistributionDomainName`; these additions grant no DNS or distribution configuration/tag writes; pass-role access targets only the collector execution role for Lambda; the initial live CI update is the account-specific check of this permission set. Setup and every other infrastructure change remain operator-managed. Ordinary configuration edits use site CI and are read at the next collection; they do not require a Lambda deployment. Bounded request/pagination and invocation retries cannot publish a partial inventory.

HTML and mutable metadata revalidate; hashed assets can be cached immutably. CloudFront invalidation and direct live checks are part of deployment. Uploading several objects is not atomic: a failure can leave mixed files until the same intended revision is redeployed. A failed build publishes nothing, and a failed deployment is reported as failed rather than hidden by a successful build.

Rollback is a reviewed Git revert on `main`, delivered through the same workflow. AWS configuration is versioned in CloudFormation, with setup and infrastructure changes performed through a separately authorized operator session. Before changing DNS authority, compare the full unrelated-record inventory and reconcile DNSSEC/parent DS state. DNS rollback requires a verified complete zone at the previous provider before restoring its delegation. The Route 53 hosted zone is retained if removed from the stack. Account-wide identity resources are reused when present rather than replaced or deleted as a side effect of this site.
